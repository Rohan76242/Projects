# Z3RO — Real Money Setup (first working slice)

This is the smallest real slice of the blueprint: opportunity discovery →
ledger → verifier, for three channels that have an actual payout API.
Nothing here moves money automatically to your bank — withdrawals stay
manual on purpose (see `ledger.record_withdrawal`, only call it yourself).

## Files

- `economy/ledger.py` — append-only SQLite ledger. Agent can never edit past
  entries or the balance directly.
- `economy/verifier.py` — the only code allowed to write income to the
  ledger, and only after checking a real third-party API/report.
- `business/opportunity_discovery.py` — generates strategy candidates for
  content (YouTube), affiliate (Amazon Associates), API service (Stripe),
  and digital products. Each candidate names its own verification source.

## What you need to actually get paid

Pick ONE channel first. Recommended: **content (YouTube)** since you
already have video generation infra.

### YouTube / AdSense
1. Enable monetization on your YouTube channel (subscriber/watch-hour
   thresholds apply — check current YouTube Partner Program requirements).
2. Create a Google Cloud project, enable the AdSense Management API.
3. OAuth2 flow to get an access token with AdSense read scope → set
   `ADSENSE_ACCESS_TOKEN` and `ADSENSE_ACCOUNT_ID` as environment variables.
4. Run `verifier.verify_youtube_adsense(...)` on a schedule (e.g. daily
   cron) — it pulls confirmed earnings and logs them to the ledger.
5. AdSense itself pays out to your real bank on its own schedule once you
   hit its payout threshold — that's your actual withdrawal, no code needed.

### Amazon Associates (affiliate)
1. Sign up for Amazon Associates, get approved, add affiliate links.
2. Amazon doesn't give individual affiliates a live commissions API —
   download your periodic earnings report CSV from the dashboard.
3. Run `verifier.verify_affiliate_amazon(strategy_id, path_to_csv)` after
   each report — it parses confirmed fees only.
4. Amazon pays out to your bank/gift card on its own schedule.

### Stripe (API microservice or digital product)
1. Create a Stripe account (real bank account attached for payouts).
2. Set `STRIPE_SECRET_KEY` as an environment variable.
3. When a customer pays, call `verifier.verify_stripe_payment(strategy_id,
   payment_intent_id)` — Stripe confirms the charge succeeded before
   anything touches the ledger.
4. Stripe pays out to your bank automatically on its default schedule
   (usually 2-7 days) — again, no agent-triggered transfer needed.

## Run order

```bash
cd z3ro
python -m business.opportunity_discovery # see candidate strategies
# pick one, wire the matching verifier, run it manually first few times
# before letting the planner call it on a schedule
python -m economy.ledger # check verified balance
```

## Safety layer (now included)

- `compliance/jurisdiction_rules.py` — human-editable rule set: hard-blocked
  channels (lending, gambling, unlicensed advice, etc.), blocked keyword
  patterns, disclosure requirements, per-platform ToS notes, and regions
  flagged for extra review.
- `compliance/legal_filter.py` — every candidate from `opportunity_discovery.py`
  must be run through `legal_filter.check(...)` before it's allowed anywhere
  near execution. Returns APPROVED / APPROVED_WITH_NOTE / REJECTED / ESCALATE,
  and logs every decision to `compliance_log.db` for audit.
- `economy/limits.py` — hard, human-editable caps: daily spend cap, per-
  transaction cap, external-action rate limits (hourly/daily), a cooldown
  after any denial, and a global `KILL_SWITCH` flag. Every spend or external
  action must call `check_spend_allowed()` / `check_external_action_allowed()`
  first — logged to `action_log.db`.
- `tools/credentials.py` — the agent never gets your real Stripe key, AdSense
  token, or a live payment card. This module issues short-lived, scoped
  credentials (read-only tokens, spend-capped virtual cards) after checking
  `limits.py`. Plug your real virtual-card provider (Privacy.com, Wise) into
  `issue_virtual_card()` — it deliberately raises `NotImplementedError` until
  you do, so nothing spends real money by accident.

### Recommended integration order

1. Candidate generated by `opportunity_discovery.py`
2. Passed to `compliance.legal_filter.check(...)` — reject/escalate stops here
3. If spending is needed, `tools.credentials.issue_virtual_card(...)` —
   capped and logged
4. Execution happens (you, manually, for now)
5. Result confirmed via the matching `economy.verifier.verify_*()` function
6. Only verified income reaches `economy.ledger.record_income(...)`
7. You manually sweep confirmed platform balances to your bank —
   `ledger.record_withdrawal()` is for logging that, never for triggering it

## What's still missing before this is "autonomous"

- `planner.py` / `strategy.py` to actually pick and sequence candidates
  instead of you running them by hand, calling the compliance filter and
  limits checks automatically at each step
- A real virtual-card provider wired into `credentials.issue_virtual_card()`
- A scheduler (cron / Task Scheduler) to run verifiers periodically
- Human-approval UI/dashboard hook for `ESCALATE` verdicts and any
  irreversible external action

Build in that order. Don't automate the planner loop until you've run each
verifier manually and trust the numbers it's logging, and don't skip
wiring the compliance filter in "just to test faster" — that's the exact
shortcut that turns into a ToS strike or a legal problem later.
